# Wellness 1.5.0 — search, saving and follow-ups

Released 3 November 2026.

- Universal search is available in the sticky app header, in record dialogs, and with Ctrl/Command K. It searches accessible pages, every guest-form section, names, paper and stored IDs, field values and notes, missions, days, appointments, follow-ups, recipes, supplies, stock movements, volunteers, attendance, edit history and the local sync queue. Results open the matching item. Opening and closing search preserves the current form; navigating away from a changed form asks before discarding it.
- Cached results appear immediately. A read-only authenticated endpoint pages through the shared catalog, without the old 500-record limit. Matching and ranking run locally, without a network call per keystroke. Refresh is available manually and every five minutes while the app is visible. Offline coverage is explicitly limited to saved device data.
- Search applies the same current role, event membership and joining-date restrictions as the record tools. The catalog is bound to the account and access scope and is encrypted inside the existing device vault. No health records are stored in localStorage or the service-worker cache.
- Assessment and consultation accept a follow-up date alone. Measurement ranges, paired blood-pressure values, units and medicine details are still validated. Native browser errors and application errors appear in a sticky form footer and floating notice. Saving buttons display an animated indicator and reject repeat clicks while saving. Shared action buttons display a delayed loading indicator during longer requests.
- Guest record saves first validate locally, then commit to encrypted IndexedDB. Only after the storage transaction completes does the form report Saved on this device. Background sync refreshes server access, resolves IDs and submits a stable operation ID. Supabase checks authorization and revisions and stores the operation transactionally. A received server save acknowledgement changes the receipt to Saved and confirmed in the database. Errors/conflicts retain the local entry and appear in Sync center. An ambiguous network response is retried with the same operation ID.
- Administrative resources, including manually scheduled appointments and recipes, save directly to Supabase and require a connection. Their confirmation follows the server response; the confirmed row is cached immediately. New resources retain one ID across retries.
- Appointments derives follow-ups directly from the latest accessible guest record, including pending offline edits. The same visit/date across screening and consultation is grouped once, with both source sections listed. Changes and clearing a date follow the source record, without creating a second database appointment or duplicate reminders. Clearing a record containing only a follow-up date resets its empty section to Waiting. Past dates say Check outcome, without assuming a missed visit.
- The floating notification button opens save results, offline/sync warnings, shared conflicts, team sync requests, app updates, and appointments/follow-ups/sessions due today through the next seven days. Notices can be dismissed per account/device. Upcoming notices work while the app is open; this release does not add scheduled background push delivery. Existing opt-in team sync pushes are unchanged.

## Validation

All 15 Node test files pass. Added search/schedule tests cover Lao text, permissions and join dates, pagination beyond 500 records, composite record keys, stock privacy, date-only entries, malformed dates, corrections and grouped follow-ups. Actual DOM tests cover all station controls, section ordering, form preservation, duplicate clicks, durable-save timing, storage and validation failures, offline versus confirmed saves, catalog refresh and notice dismissal. Isolated PostgreSQL tests exercise the production functions, including date-only follow-up persistence and existing access/revision controls. Browser QA uses fictional records, including the date-only Save → confirmation → Appointments flow and phone layout.

The original section/grouping audit remains in director-request-audit-2026-11-03.md. No schema migration or real guest-data mutation is part of this release.
